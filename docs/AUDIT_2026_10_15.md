## B. Findings, ranked

### Critical

**C1. Two-node Art-Net feedback latch survives the fix (audit #2 residual). C**
- **Where:** main.cpp:1224-1249 (`pollArtNet`), :1201-1221 (`sendArtNetOut`), :1180 (HTP).
- **Input:** nodes A and B, both with Art OUT on (default universe 0/0/0, default subnet broadcast, default mode MERGE_HTP).
- **What happens:** A's merged frame arrives at B from A's IP, which is not B's own IP, so the check at :1234 passes. B outputs `max(web_B, art_B)` and broadcasts it, and A takes it back. Blackout zeroes only `webVals`, so the rig latches at the highest level either node ever produced.
- **Fix:** drop ArtDmx from any IP that is a known vizzz peer whose Art OUT is enabled, or tag our own Art OUT (for example a non-zero `Physical` byte plus a peer-MAC check) and ignore tagged packets on input. Better: never re-emit merged output on the universe the node listens to.
- **Standard:** Art-Net 4 says ArtDmx should be unicast to subscribers (broadcast is deprecated), which also removes the loop.
- **Fixed:** d0eb01b — our Art OUT tags ArtDmx Physical=0x76; a node with Art OUT on drops tagged frames, so two re-emitting nodes cannot latch; master→slave unchanged (slave has Art OUT off). Not yet seen on two real nodes.

**C2. Cross-task String race: the readers still take no lock (audit #4 residual). C**
- **Where:** `artOutTarget()` reads `artOutPeerIp` at :536 with no lock. It is called from loop() through `sendArtNetOut` (:1218) and from `fillStatusJSON` (:1956). `fillStatusJSON` also reads `nodeName`, `apSsid`, `staSSID` and `mdnsName` unlocked (:1957-1960), from loop() (WebSocket push :3157) and from the AsyncTCP task (/status). `mdnsName` is written with no lock at all, from both tasks: `startMdns()` from `/node/set` (:2636) and from loop() on link-up (:3092).
- **Input:** `/artout/peer?ip=<longer string>` or `/node/set?name=` while a WebSocket client is open.
- **What happens:** `String::operator=` reallocates and frees the buffer the loop task is copying from. The result is a heap use-after-free, a crash, and DMX frozen on its last frame.
- **Fix:** read every shared String into a local `char[]` under `gLock`. Keep `artOutPeerIp` as a cached `IPAddress` (a 4-byte copy). Build `mdnsName` into a fixed `char[32]` under the lock.
- **Fixed:** d17912c — shared Strings read via an `IdentitySnap` copied under gLock; peer IP is a `std::atomic<uint32_t>` (strict dotted quad, else 400); `mdnsName` a fixed `char[32]`; MDNS restart and /discover beacon deferred to loop().

### High

**H1. A 1-7 character AP password bricks an AP_ONLY node; an empty one opens the AP. C**
- **Where:** main.cpp:2633 caps the password at 63 characters but sets no minimum.
- **What happens:** core 2.0.17 `WiFi.softAP()` returns false when `0 < strlen(pass) < 8` (WiFiAP.cpp:145-148). `startSoftAP()` ignores that return (:548-551). After `/node/set?ap_pass=abc` and any reboot, a NET_AP_ONLY node has no network at all: no AP and no STA. `/factory-reset` is unreachable, so recovery is a serial reflash. `ap_pass=` (empty) gives an open AP that controls the rig.
- **Fix:** reject `ap_pass` unless it is 8-63 printable characters, per IEEE 802.11i (the WPA2 passphrase rule). Check the `softAP()` return; on failure, fall back to the generated SSID with the build-time password.
- **Fixed:** 48ae2e9 — /node/set rejects ap_pass unless 8–63 printable (`vizzz::isValidWpaPassphrase`, IEEE 802.11i H.4.1) and empty ap_ssid; loadConfig repairs a stored bad pass; `softAP()` refusal falls back to MAC SSID + build pass, logged and shown as `ap_fb` in /status.

**H2. Blackout is undone by a running cue list. C**
- **Where:** `routeBlackout` (:2402-2416), the deferred blackout (:3061-3066) and `/net/blackout` (:2880-2889) never clear `cueRunning`. `tickCueEngine` (:877-890) then fires the next step and fades back to a scene.
- **What happens:** with the cue list running, Blackout lasts at most `fade+dwell` (default 2 s) and the rig comes back by itself.
- **Fix:** Blackout sets `cueRunning=false` and `fxEnabled=false`, as `/panic` does at :3053-3055.
- **Fixed:** 617e4d0 — one `applyBlackout_locked()` for /blackout, /net/blackout and the deferred path also sets `cueRunning=false`, `fxEnabled=false`.

### Medium

**M1. Cue engine spins at loop rate when fade + dwell = 0. C**
- **Where:** `/cue/set` takes `dwell=0&fade=0` unclamped (:2758-2759), so `cueStepMs=0` (:872). Then `(now-cueStartedMs) < 0` is never true (:882), and every loop() iteration (thousands per second between DMX frames) calls `triggerCueStep` → `loadScene` (an NVS read) on the DMX task.
- **What happens:** scenes alternate at frame rate (a flicker hazard), and NVS is hammered through the shared `prefs` (makes audit #6 likely).
- **Fix:** clamp `dwell+fade` to at least 50 ms at set time and in `triggerCueStep`.
- **Fixed:** 601d02e — step = `vizzz::cueStepMs()` ≥ 50 ms in triggerCueStep/tickCueEngine; /cue/set raises dwell so fade+dwell ≥ 50.

**M2. sACN listens on universe 0 by default, which E1.31 reserves. C**
- **Where:** `universe()` (:104) is used directly for sACN (:1276) and for the multicast group (:746, giving 239.255.0.0). The live node reports `uni15:0`.
- **Standard:** ANSI E1.31-2018 §6.2.7 makes universes 0 and 64000-65535 reserved; data universes are 1-63999.
- **What happens:** a compliant sACN source cannot drive a default node.
- **Fix:** sACN universe = Art-Net port-address + 1 (the common convention), or a separate sACN universe setting with a minimum of 1.
- **Fixed:** d0eb01b — sACN universe = Port-Address + 1 (default 1), multicast group follows; same fix as 2-H3.

**M3. sACN option bits, priority and loss timing are ignored. C**
- **Where:** `pollSacn` (:1252-1290) never reads `pkt[112]` (Options) or `pkt[108]` (Priority).
- **What happens:**
  - Preview_Data (0x80) packets drive live output, though E1.31 §6.2.6 says receivers shall ignore preview data for live output.
  - Stream_Terminated (0x40) data is applied as levels instead of ending the source (§6.2.6).
  - Two sources simply overwrite each other, with no per-source priority (§6.2.3).
  - The timeout is 3000 ms (:39), but E1.31 §6.7.1 sets the network data loss timeout at 2500 ms.
- **Fix:** skip the packet when bit 0x80 is set; when 0x40 is set, set `lastSacnMs=0`; track source CID and priority (take the highest, then HTP among equals); set the timeout to 2500 ms.
- **Fixed:** d0eb01b — preview skipped, terminated drops the source at once, priority (highest wins, HTP among equals), §6.7.2 sequence window, 2.5 s loss per source; tests in cd70eed.

**M4. Art-Net: no source merging and no ArtPoll reply. C**
- **Merging:** `pollArtNet` copies each ArtDmx over `artVals` (:1245). With two controllers on the universe, the output flips between them at packet rate. Art-Net 4 ("Data merging") requires a node to merge two sources (HTP or LTP) and ignore a third.
- **ArtPoll:** there is no OpPoll (0x2000) handling (grep: none), so consoles that patch by ArtPoll discovery (Art-Net 4: every node shall reply with ArtPollReply) never see the node.
- **Fix:** keep two source slots keyed by IP with a 10 s expiry, merge them HTP, and answer ArtPoll with ArtPollReply.
- **Fixed:** d0eb01b — ArtPollReply (2-H1) and two-source HTP merge by IP, third ignored, 10 s cancel (2-M1).

**M5. `/net/blackout` still drops a blackout on a busy lock. C**
- **Where:** :2880-2884 returns 503 and does nothing after 20 ms. This is the drop that `/blackout` fixed; the fleet route was missed.
- **Fix:** the same deferral, `pendingBlackout=true`, then enqueue the broadcast.
- **Fixed:** 617e4d0 — busy lock sets `pendingBlackout` (202) and the fleet broadcast is still queued.

**M6. Up to about 10 s of no DMX after every boot or reboot. C**
- **Where:** `startWiFi()` blocks up to 10 s waiting for STA (:596-597) before loop() sends the first frame. `setupDMX` only installs the driver.
- **What happens:** `/reboot`, `/netmode/set`, `/web/set` or a brown-out during a show with STA credentials but no router means more than 10 s of signal loss. Fixtures then do whatever their loss behaviour is. ANSI E1.11 leaves loss handling to the receiver, so it is unpredictable.
- **Fix:** start a DMX output task (or `dmx_send` from a timer) before WiFi, and make STA join non-blocking.
- **Fixed:** ac0d3cd — STA join is non-blocking; `serviceStaJoin()` in loop() owns the 10 s window and the STA_ONLY safety AP. Not done: a separate DMX task started before WiFi; reset→first-frame time is unmeasured (owed on the node).

**M7. OSC float arguments are truncated to integers. P**
- **Where:** `v = int32_t(fv)` (:1076).
- **What happens:** controllers that send normalised 0.0-1.0 floats (TouchOSC's default fader range) set `/master 0.8` to 0 (dark) and `/ch/N 1.0` to 1. NaN, Inf or |f| ≥ 2^31 is undefined behaviour in the float-to-int conversion (C++ [conv.fpint]).
- **Fix:** if `0 ≤ f ≤ 1`, use `lroundf(f*255)`; otherwise clamp `f` with `isfinite` before converting.
- **Fixed:** df638a1 — floats 0.0–1.0 on level addresses map to 0–255 (lroundf), larger floats clamp, NaN/Inf safe; index addresses round and clamp.

**M8. No watchdog on the DMX path. P**
- **Where:** there is no `esp_task_wdt` anywhere (grep count 0). The Arduino loop watchdog is off by default, and `pendingPanic` and `pendingBlackout` wait with `portMAX_DELAY` (:3047, :3062).
- **What happens:** a hung loop() freezes DMX on its last frame with no reboot and no log.
- **Fix:** `enableLoopWDT()` or `esp_task_wdt_add(NULL)` with a timeout of about 2 s, a bounded lock wait, and a reset reason in /status (ESP-IDF "Watchdogs" API reference).
- **Fixed:** 718a6eb — `enableLoopWDT()` (TWDT 5 s, panic; not 2 s: `esp_task_wdt_init` would also shorten the IDLE0 check, unmeasured); panic/blackout waits bounded to 500 ms; `rst` (esp_reset_reason) in /status.

**M9. AP_STA: a STA without a router keeps moving the soft-AP channel. P**
- **What happens:** with STA credentials set and the router absent (a typical venue), reconnect scans change the radio channel. The soft-AP follows the STA channel (ESP-IDF Wi-Fi driver guide, station/AP coexistence), so the operator's phone on the node's AP drops repeatedly.
- **Fix:** after N failed joins, stop STA retries (`setAutoReconnect(false)`) and retry on a slow timer. Alternatively, pin the AP channel and drop the STA when AP clients are present.
- **Fixed:** ac0d3cd — with the AP up, a failed 10 s join parks the STA (auto-reconnect off, disconnect) and retries after `vizzz::staRetryDelayMs` (30 s doubling to 300 s), only with no AP client; /wifi/set resets it.

- **DMX timing:**
  - Break 176 µs and MAB 12 µs (esp_dmx `types.h:105,112`) meet ANSI E1.11 (break ≥ 92 µs, MAB ≥ 12 µs).
  - The frame is 513 slots (`dmx_send` → `DMX_PACKET_SIZE`) at about 43 Hz, within E1.11's 44 Hz maximum for a full universe.
  - The order write → send → `wait_sent(30 ms)` never writes into a frame in flight.
- **Fade math:** `delta*k` at most ±65 025, no overflow. `fxApplyDepth` ≤ 255.
- **FX:** BPM is clamped to 20-240 everywhere (:1132, :2817, :2837), and the zero beat is guarded (:940).

- **Peer GET:** the path allowlist and clean-path check are sound (:428-444). The known-peer check is done under the lock (:2867).
- **Factory reset:** uses its own `Preferences` instances (no shared-handle race) and clears all four app namespaces.
- **Heap churn on the loop path:** small and bounded (MAC and IP Strings per beacon and per 400 ms push). There is no unbounded growth.

**H1. The node never answers ArtPoll, so di's desk can never discover it. CONFIRMED.**

**H3. The sACN universe is off by one against di and E1.31, and at the default it is the reserved universe 0. CONFIRMED (live `uni15=0`).**

## How the node fits di.iiii's desk

### (a) Does di's desk reach this node today?

**Art-Net: yes, under four conditions.**
1. di's desk output is ON. It is OFF by default inside di.iiii (`desk.js:250-253`).
2. The driver is `artnet`.
3. Fixtures or held channels are on desk "Universe 1". That is index 0, which goes on the wire as Port-Address 0, i.e. net 0, sub 0, uni 0.
4. The di host is on the node's subnet. aylmo is 192.168.88.231/24, so the broadcasts to 192.168.88.255 and 255.255.255.255 reach 192.168.88.66. Unicast mode with target `192.168.88.66` also works.

**What the node listens on:** Port-Address 0 (live `/status`: net 0, sub 0, uni 0, `uni15` 0, `mode_name MERGE_HTP`).

**What happens to di's levels on the node:** the desk's frame is HTP-merged with the web/VJ layer. Then master is applied, the level is clamped to 245 (or 96 in burn-safe), and changes are slewed at 18 per 23 ms frame. A cut from 0 to 255 therefore takes about 320 ms.

**Desk on another universe:** a desk universe other than U1 reaches the node only after `/artnet/set` moves the node to match.

**sACN: no.** The node listens on sACN 0 and di sends 1 (H3).

**Not proven on the wire:** sending was out of scope for this read-only audit.

### (b) What the node lacks for di to list it as discovered

- **A reply to ArtPoll (H1).** It must accept ArtPoll packets of 14 bytes or more. It must answer with an ArtPollReply of 239 bytes or more, sent to the poller's IP on UDP 6454. di's socket is bound to 0.0.0.0:6454 and also receives a directed broadcast.
- **Fields di reads (`artnet.js:51-70`):** ID `Art-Net\0` (0–7); OpCode 0x2100 LE (8–9); IP (10–13); Port 0x1936 LE (14–15); NetSwitch = `artNet` (18); SubSwitch = `artSubnet` (19); ShortName 18 B (26); LongName 64 B (44); NumPorts = 1, big-endian (172–173); SwOut[0] = `artUni` (190).
- **Fields the spec requires that di ignores:** PortTypes[0] 0x80 DMX output (174); GoodOutput[0] data bit (182); Style 0x00 StNode (200); MAC (201–206); BindIp (207–210); BindIndex 1 (211).
- **Without this:** the node appears only as a typed-in device with no age or universe. Unicast to it still works.

### (c) What di can and cannot do with the node

**Desk over Art-Net:**
- **Can:**
  - Drive all 512 channels of one universe at 40 Hz.
  - HTP-merge with the node's web, VJ, FX and scene layer in MERGE_HTP.
  - Have its blackout (all zeros, still sent) pull the desk's share to 0.
- **Cannot:**
  - See the node in discovery (H1).
  - Know the node's mode, master or safety clamp. Desk 255 comes out as 245, and the node's master scales the desk too.
  - Black out the node's web layer.
  - Share the universe with another Art-Net source without flicker (M1).
  - After di stops, keep its look: it is gone 3 s later (L9).

**DMX Out over HTTP (`dmxRigClient` and `DmxOutPanelWindow`):**
- **Can:**
  - Read `/status`, which has ACAO.
  - Set master (`/master?v=`).
  - Set one channel at a time, 1–240 (`/set?ch=&v=`), throttled to one send per 100 ms, latest value wins.
  - Clear the web layer (`/blackout`).
  - Only from an http page on the same LAN, e.g. diiii.localhost. A https page is blocked as mixed content (`isRigBlocked`).
- **Cannot:**
  - See whether a command worked, because commands are `no-cors` (503 "busy" is lost).
  - Black out the desk layer (M8).
  - Reach channels 241–512.
  - Learn the node's routes from the manifest, since `/set` is missing from it (M4).
  - Read levels. `/page` and `/monitor` carry ACAO but are unused.

**Both at once:** the two inputs combine HTP on the node: the web layer (DMX Out) against the Art-Net layer (desk). The node's master scales both.

### (d) The smallest change set for a clean merge

**Firmware:**
1. **ArtPoll → ArtPollReply (H1).** Accept 14 bytes or more; send the 239-byte reply with the fields in (b).
2. **Socket refresh off the web task (H4).** Move it into `loop()` behind a flag.
3. **Art-Net two-source HTP merge with a timeout per source (M1).** Needed only if more than one Art-Net source will ever share universe 0. This includes a peer's Art-Net OUT.
4. **Manifest (M4).** Complete the route list (add `/set`, `/panic` and the rest) and put the git hash in `firmware.tag`, so di can trust what the node says it runs.
5. **sACN universe = Port-Address + 1 (H3).** Needed only if di will drive the node over sACN.

**di:**
1. **Until firmware item 1 lands:** add `192.168.88.66` as a unicast target, or keep broadcast with aylmo on 192.168.88.0/24, and turn desk output ON. This is a config step, not code.
2. **Decision owed (owner):** DMX Out's "blackout" either stays a web-layer-only clear and is labelled that way, or is mapped to `/panic`. `/panic` kills everything, but leaves the node in WEB_ONLY until `/mode/set?m=2`.
3. **Rule while running:** keep the node's Art-Net OUT off whenever di's DMX input listens on the same universe (M11).

Nothing else is needed for the merge itself: the node's MERGE_HTP already combines the desk with its web/VJ layer.
